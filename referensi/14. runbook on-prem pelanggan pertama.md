# Runbook — Beli Putus (On-Prem) Pelanggan Pertama

**Untuk:** menyerahkan ApotikFlow ke pembeli pertama (lisensi perpetual, server di lokasi pelanggan).  
**Estimasi waktu:** vendor 1–2 jam build · pelanggan 3–5 jam instalasi + wizard.  
**Relasi:** `referensi/10. checklist beli putus.md`, `deploy/README.md`, `scripts/build-release.sh`

---

## 0. Ringkasan

```text
[VENDOR]  build-release.sh + generate lisensi + kirim ZIP
              │
              ▼
[SERVER PELANGGAN]  PostgreSQL + API :3000 (+ nginx web opsional)
              ▲
              │  Atur alamat server (pre-login)
[PC/TABLET KASIR]  APK atau browser → Wizard → operasional
```

| Peran | Tanggung jawab |
|-------|----------------|
| **Vendor (Anda)** | Build paket, generate lisensi, bimbing instalasi |
| **IT pelanggan** | Server, PostgreSQL, jaringan LAN |
| **Super Admin pelanggan** | Wizard DB, aktivasi lisensi, buat tenant |
| **Owner apotek** | Cabang, user, master data, go-live harian |

## Fase A — Vendor: siapkan paket kiriman (1–2 jam)

### A1. Build paket rilis

```bash
cd /path/ke/apotek
chmod +x scripts/build-release.sh
./scripts/build-release.sh
```

Output di `release/`:

| File | Isi |
|------|-----|
| `apotikflow-backend.zip` | API + prisma + systemd + nginx example |
| `apotikflow-web.zip` | Flutter web (jika build berhasil) |
| `10. checklist beli putus.md` | Panduan panjang |
| `README-RILIS.txt` | Ringkasan |

Build tambahan per platform pelanggan:

```bash
cd app
flutter build apk --release -t lib/main_production.dart    # Android kasir
# flutter build windows --release -t lib/main_production.dart  # PC Windows
```

### A2. Generate lisensi perpetual

Di mesin vendor, `LICENSE_SECRET` harus **sama persis** dengan yang akan dipasang di server pelanggan.

```bash
cd api
# Pastikan LICENSE_SECRET di .env vendor sudah kuat & dicatat
npm run license:generate -- \
  --customer "Apotek Sejahtera" \
  --type perpetual \
  --plan single \
  --tenant APOTEK01 \
  --max-branches 3
```

Catat di lembar serah terima:

- [ ] Nama pelanggan
- [ ] Kode tenant (`APOTEK01`)
- [ ] `max_branches`
- [ ] Kode lisensi (kirim **terpisah** dari ZIP, channel aman)
- [ ] `LICENSE_SECRET` untuk server pelanggan (kirim terpisah / dijelaskan saat remote)
- [ ] Versi build & tanggal

### A3. Isi media kiriman

| # | Item | Format |
|---|------|--------|
| 1 | Backend | `apotikflow-backend.zip` |
| 2 | App | APK +/atau `apotikflow-web.zip` |
| 3 | Lisensi | Kode teks (WhatsApp terenkripsi / dokumen terpisah) |
| 4 | Runbook ini | PDF atau markdown |
| 5 | Akun bootstrap | Email super admin dari seed — **instruksikan ganti password** |

## Fase B — IT pelanggan: server (2–3 jam)

### B1. Spesifikasi & jaringan

| Item | Nilai |
|------|-------|
| OS | Ubuntu 22.04 LTS (disarankan) |
| RAM | 4 GB+ |
| Node.js | 20 LTS |
| PostgreSQL | 16 |
| IP server | Contoh `192.168.1.10` (statis di LAN) |
| Port API | **3000** terbuka di LAN |
| Port 5432 | **Hanya localhost** |

```bash
sudo apt update
sudo apt install -y postgresql-16 nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
```

### B2. Database

```bash
sudo -u postgres createdb apotikflow
# Catat user postgres + password untuk wizard nanti
```

### B3. Deploy backend

```bash
sudo mkdir -p /opt/apotikflow-backend
cd /opt/apotikflow-backend
unzip /path/apotikflow-backend.zip   # isi folder apotikflow-backend/

cp .env.example .env
nano .env
```

Minimal `.env` sebelum wizard:

```env
DEPLOYMENT_MODE=on_prem
NODE_ENV=production

LICENSE_SECRET=<SAMA_DENGAN_VENDOR_SAAT_GENERATE>
JWT_SECRET=<acak-panjang-unik>
JWT_REFRESH_SECRET=<acak-panjang-unik>

PORT=3000
API_PREFIX=api/v1
CORS_ORIGIN=*
ENABLE_PLATFORM=true

# Sementara — user postgres sampai wizard DB selesai:
DATABASE_URL=postgresql://postgres:PASSWORD@127.0.0.1:5432/apotikflow?schema=public
PLATFORM_DATABASE_URL=postgresql://postgres:PASSWORD@127.0.0.1:5432/apotikflow?schema=public
```

```bash
npm ci --omit=dev
npx prisma migrate deploy
npm run db:seed    # super admin awal — ganti password setelah wizard
node dist/main.js   # tes dulu, lalu pasang systemd
```

Verifikasi:

```bash
curl http://127.0.0.1:3000/api/v1/health
```

### B4. Service systemd (auto-start)

```bash
sudo useradd -r -s /bin/false apotikflow || true
sudo chown -R apotikflow:apotikflow /opt/apotikflow-backend

sudo cp deploy-extras/apotikflow-api.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable apotikflow-api
sudo systemctl start apotikflow-api
sudo systemctl status apotikflow-api
```

### B5. Flutter web di nginx (opsional)

Jika tidak pakai APK saja:

```bash
sudo mkdir -p /var/www/apotikflow-web
sudo unzip apotikflow-web.zip -d /var/www/
sudo cp deploy-extras/apotikflow.conf.example /etc/nginx/sites-available/apotikflow
# Edit server_name & root
sudo ln -s /etc/nginx/sites-available/apotikflow /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

Akses dari LAN: `http://192.168.1.10/` (web) atau `http://192.168.1.10:3000/api/v1/health` (API).

## Fase C — Super Admin pelanggan: wizard di app (1–2 jam)

### C1. Atur server (sebelum login)

1. Install APK / buka web di browser PC kasir
2. Di halaman login → **Atur alamat server**
3. Isi: `http://192.168.1.10:3000` (tanpa `/api/v1`)
4. **Tes koneksi** → Simpan

### C2. Login & wizard (urutan wajib)

Login: super admin dari seed → **ganti password segera**.

| Langkah | Menu di app | Hasil yang diharapkan |
|---------|-------------|------------------------|
| 1 | Sudah dari C1 | Koneksi API OK |
| 2 | **Database On-Prem** | Tes koneksi → migrasi → Terapkan & simpan |
| 3 | **Restart API** | `sudo systemctl restart apotikflow-api` |
| 4 | **Aktivasi lisensi on-prem** | Paste kode vendor → status valid |
| 5 | **Platform → Kelola Tenant** | Buat tenant + akun owner |

Detail Database On-Prem:

1. Tes koneksi (user `postgres`)
2. Buat database (jika belum)
3. Migrasi schema
4. Terapkan permission role `apotikflow_app` / `apotikflow_platform`
5. **Restart API** — wajib

### C3. Serah terima ke Owner

- [ ] Owner login berhasil
- [ ] Status lisensi: valid, `max_branches` sesuai paket
- [ ] Buat cabang pertama (+ gudang pusat jika perlu)
- [ ] Buat user kasir, gudang, apoteker
- [ ] Demo: buat order → telaah (jika ada resep) → bayar di kasir
- [ ] Semua password default diganti

## Fase D — Checklist keamanan go-live

- [ ] `LICENSE_SECRET` sama vendor ↔ server pelanggan
- [ ] `JWT_*` unik, bukan contoh `.env.example`
- [ ] PostgreSQL port 5432 tidak ke internet
- [ ] Password `postgres` / role app tidak default dev
- [ ] Backup harian PostgreSQL dijadwalkan & pernah diuji restore
- [ ] Folder `data/` dan `uploads/` ikut backup
- [ ] Akun seed tidak dipakai operasional

Backup contoh:

```bash
sudo -u postgres pg_dump apotikflow | gzip > /backup/apotikflow-$(date +%F).sql.gz
```

## Fase E — Troubleshooting (sesi instalasi pertama)

| Gejala | Penyebab | Solusi |
|--------|----------|--------|
| App timeout | API mati / firewall | `curl http://IP:3000/api/v1/health`, buka port 3000 di LAN |
| Aktivasi lisensi gagal | `LICENSE_SECRET` beda | Samakan dengan vendor |
| Wizard DB gagal migrasi | User DB kurang hak | Pakai `postgres` atau owner DB |
| Setelah Terapkan masih error DB | API belum restart | `systemctl restart apotikflow-api` |
| Menu Database On-Prem tidak ada | Bukan on-prem | `DEPLOYMENT_MODE=on_prem` di `.env` |
| Tambah cabang ditolak | Melebihi lisensi | Naikkan `max_branches` (generate lisensi baru) |
| QRIS gagal | Provider mock | Set `QRIS_PROVIDER` + kredensial di `.env` |

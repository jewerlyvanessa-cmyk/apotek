# Checklist Kirim Paket Beli Putus (On-Prem Perpetual)

Dokumen ini untuk **tim vendor / IT** saat menyerahkan ApotikFlow ke pelanggan beli putus.  
Target: pelanggan bisa membuka **halaman login** dan menyelesaikan setup tanpa akses source code.

---

## Ringkasan arsitektur

| Lokasi | Yang diinstall | Yang tidak |
|--------|----------------|------------|
| **Server pembeli** | PostgreSQL, backend `deploy/backend/`, (opsional) Redis, (opsional) Flutter web di nginx | Flutter SDK, source `app/`, `npm run start:dev` |
| **Perangkat staff** | APK / exe / macOS app / browser ke web build | Backend API |

```text
[VENDOR]  build backend + app + lisensi
              │
              ▼
[SERVER]    PostgreSQL + node dist/main :3000
              ▲
              │ HTTP (Atur alamat server di app)
[CLIENT]    Flutter → Halaman Login → Wizard Setup
```

---

## A. Persiapan vendor (sebelum kirim)

### A1. Build backend produksi

```bash
cd api
npm run deploy:prepare
```

Hasil: folder `deploy/backend/` (sudah berisi `dist/`, `prisma/`, `package.json`, `.env.example`).

Verifikasi:

- [ ] `deploy/backend/dist/main.js` ada
- [ ] `deploy/backend/prisma/schema.prisma` sinkron dengan `api/prisma` (script `prepare-deploy` gagal jika tidak)

### A2. Build aplikasi Flutter (pilih sesuai kebutuhan pelanggan)

```bash
cd app
flutter pub get

# Android
flutter build apk --release -t lib/main_production.dart

# Web (host di nginx server yang sama — opsional)
flutter build web --release -t lib/main_production.dart

# Windows / macOS (jika diperlukan)
flutter build windows --release -t lib/main_production.dart
flutter build macos --release -t lib/main_production.dart
```

- [ ] Artefak build disalin ke media kiriman (USB / ZIP / installer)
- [ ] Catat versi build & tanggal rilis

> Build production memakai URL cloud bawaan. Pelanggan **wajib** mengatur alamat server lewat **Login → Atur alamat server** saat instalasi pertama.

### A3. Generate lisensi perpetual

Pastikan `LICENSE_SECRET` di server pelanggan **sama** dengan yang dipakai saat generate.

```bash
cd api
# Set LICENSE_SECRET di .env vendor (jangan pakai default production)
npm run license:generate -- \
  --customer "PT Apotek Contoh" \
  --type perpetual \
  --plan single \
  --tenant APOTEK01 \
  --max-branches 3
```

- [ ] Simpan kode lisensi (kirim terpisah / aman)
- [ ] Catat: nama pelanggan, kode tenant, `max_branches`, tanggal kirim

### A4. Paket yang dikirim ke pelanggan

| Item | Format | Keterangan |
|------|--------|------------|
| Backend | Folder `deploy/backend/` atau `.zip` | Bundle produksi |
| Aplikasi | APK / installer / `build/web/` | Sesuai platform |
| Lisensi | Kode teks (channel aman) | Aktivasi on-prem |
| Panduan | Dokumen ini (ringkas) | Langkah setup |
| Akun awal | Email + password sementara Super Admin | Ganti setelah go-live |

Opsional (sudah tersedia di repo):

- [x] Script systemd — `deploy/systemd/apotikflow-api.service`
- [x] Contoh nginx — `deploy/nginx/apotikflow.conf.example`
- [x] Paket rilis — `./scripts/build-release.sh`

## B. Spesifikasi server pembeli

### Minimum

| Komponen | Versi disarankan |
|----------|------------------|
| OS | Linux (Ubuntu 22.04+) atau Windows Server |
| CPU/RAM | 2 vCPU, 4 GB RAM (naikkan jika banyak cabang) |
| Disk | 40 GB+ SSD |
| Node.js | 20 LTS |
| PostgreSQL | 16 |
| Jaringan | LAN stabil; port **3000** (API) terbuka di jaringan internal |

### Port & keamanan jaringan

| Port | Layanan | Akses |
|------|---------|-------|
| 3000 | API NestJS | Internal LAN / VPN |
| 5432 | PostgreSQL | **Hanya localhost** (jangan buka ke internet) |
| 80/443 | nginx (opsional, Flutter web) | Internal LAN |

- [ ] Firewall: tutup 5432 dari luar
- [ ] Backup otomatis PostgreSQL dijadwalkan di server

## C. Instalasi di server pembeli

### C1. PostgreSQL

```bash
# Contoh Linux — sesuaikan dengan OS pelanggan
sudo apt install postgresql-16
sudo -u postgres createdb apotikflow
```

- [ ] PostgreSQL berjalan
- [ ] User admin (`postgres` atau dedicated) dan password dicatat

### C2. Deploy backend

```bash
sudo mkdir -p /opt/apotikflow-backend
sudo cp -r deploy/backend/* /opt/apotikflow-backend/
cd /opt/apotikflow-backend

cp .env.example .env
```

Edit `.env` minimal:

```env
DEPLOYMENT_MODE=on_prem
LICENSE_SECRET=<sama-dengan-saat-generate-lisensi>
JWT_SECRET=<string-acak-panjang-unik>
JWT_REFRESH_SECRET=<string-acak-panjang-unik>
PORT=3000
API_PREFIX=api/v1
CORS_ORIGIN=*

# Sementara — sampai wizard DB selesai (user postgres / owner DB):
DATABASE_URL=postgresql://postgres:PASSWORD@127.0.0.1:5432/apotikflow?schema=public
PLATFORM_DATABASE_URL=postgresql://postgres:PASSWORD@127.0.0.1:5432/apotikflow?schema=public
```

```bash
npm ci --omit=dev
npx prisma migrate deploy
npm run db:seed    # membuat superadmin@apotikflow.com (ganti password setelah go-live)
node dist/main
```

Verifikasi API:

```bash
curl http://127.0.0.1:3000/api/v1/health
# success: true
```

- [ ] API merespons `/api/v1/health`
- [ ] Folder `data/` dapat ditulis (untuk `config.env` setelah wizard DB)

### C3. Jalankan sebagai service (disarankan)

- [ ] API dijalankan dengan **systemd**, **PM2**, atau Windows Service
- [ ] Auto-restart jika crash
- [ ] Log rotasi dikonfigurasi

### C4. Host Flutter web (opsional)

Jika tidak memakai APK/installer, salin `app/build/web/` ke nginx:

```nginx
server {
  listen 80;
  server_name apotikflow.lan;
  root /var/www/apotikflow-web;
  index index.html;
  location / {
    try_files $uri $uri/ /index.html;
  }
}
```

- [ ] Web dapat dibuka dari browser LAN
- [ ] Staff tetap perlu **Atur alamat server** jika API tidak di URL bawaan build

## D. Setup di perangkat pelanggan (first run)

### D1. Buka aplikasi → halaman login

1. Install APK / buka web / jalankan desktop app
2. Tap **Atur alamat server**
3. Isi URL API, contoh: `http://192.168.1.10:3000`
4. **Tes koneksi** → harus sukses
5. **Simpan** → kembali ke login

- [ ] Halaman login tampil
- [ ] Tidak ada error koneksi ke server

### D2. Login Super Admin → Wizard Setup

Login: `superadmin@apotikflow.com` (password dari seed — **wajib diganti**)

Menu **Platform Admin → Wizard Setup** (urutan):

| # | Langkah | Menu |
|---|---------|------|
| 1 | Alamat server API | Sudah dari D1 (bisa dicek ulang) |
| 2 | Database PostgreSQL | **Database On-Prem** |
| 3 | Aktivasi lisensi | **Login → Aktivasi lisensi on-prem** atau Platform |
| 4 | Tenant & owner | **Kelola Tenant** — buat tenant + akun owner |

#### Database On-Prem (langkah 2)

Urutan di UI:

1. **Tes koneksi** (user admin PostgreSQL)
2. **Buat database** (jika belum ada — biasanya sudah ada dari C1)
3. **Migrasi schema**
4. **Terapkan & simpan**
5. **Restart API** (`node dist/main` atau restart service)

- [ ] Status: "Database terhubung & schema siap"
- [ ] Role `apotikflow_app` dan `apotikflow_platform` terbuat
- [ ] API sudah di-restart setelah terapkan config

#### Aktivasi lisensi (langkah 3)

- [ ] Paste kode dari vendor
- [ ] Status lisensi instalasi: valid

#### Tenant & owner (langkah 4)

- [ ] Tenant pertama dibuat
- [ ] Akun owner dibuat & bisa login
- [ ] Jumlah cabang tidak melebihi `max_branches` lisensi

### D3. Serah terima operasional

- [ ] Owner login → cek **Status Lisensi**
- [ ] Buat cabang sesuai paket
- [ ] Buat user kasir / gudang / dll.
- [ ] Password Super Admin & owner diganti
- [ ] Demo singkat alur: order → kasir → bayar

## E. Checklist keamanan go-live

- [ ] `JWT_SECRET`, `JWT_REFRESH_SECRET`, `LICENSE_SECRET` unik per pelanggan
- [ ] Password PostgreSQL & role app tidak memakai default dev (`apotikflow_app_secret`, dll.)
- [ ] Port 5432 tidak exposed ke internet
- [ ] HTTPS / reverse proxy jika API diakses lewat jaringan lebih luas
- [ ] Backup harian PostgreSQL teruji (restore pernah dicoba)
- [ ] Akun demo/seed tidak dipakai di produksi (ganti semua password)

## F. Troubleshooting cepat

| Gejala | Kemungkinan penyebab | Tindakan |
|--------|---------------------|----------|
| App tidak bisa login, timeout | URL server salah / API mati | Cek `curl .../health`, firewall port 3000 |
| Login: server error | DB belum connect / migrasi belum jalan | Cek log API, jalankan wizard DB |
| Menu Database On-Prem tidak muncul | Bukan mode on-prem perpetual | Pastikan `DEPLOYMENT_MODE=on_prem` + lisensi perpetual |
| Aktivasi lisensi gagal | `LICENSE_SECRET` beda dengan saat generate | Samakan secret di `.env` server |
| Wizard DB: migrasi gagal | User migrate tidak punya hak | Pakai user `postgres` atau owner DB |
| Setelah "Terapkan & simpan" masih error DB | API belum restart | Restart service API |
| Tambah cabang ditolak | Melebihi `max_branches` | Upgrade lisensi / generate ulang |
